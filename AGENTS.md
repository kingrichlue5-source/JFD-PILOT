# AGENTS.md

## Project

JFD Hospital Management System — a Django 6.1 + DRF application for JFD Memorial Regional Referral Hospital (Liberia). Provides REST APIs and server-rendered templates for patient registration, triage, OPD/IPD/ER clinical workflows, pharmacy dispensing, billing, inventory, and HMIS/DHIS2 reporting.

## Quick commands

```bash
# Activate venv first (Windows)
venv\Scripts\activate

# Run dev server
python manage.py runserver

# Run all tests
python manage.py test

# Run a single test module
python manage.py test tests.test_patient_api

# Seed demo data (standalone script)
python seed_data.py

# Seed via management command
python manage.py seed_data

# Collect static files
python manage.py collectstatic

# Generate HMIS report
python manage.py generate_hmis_report
```

No linting, typecheck, or formatter is configured in this repo.

## Database

- **DEBUG=True** (default): SQLite at `db.sqlite3`. Works out of the box with `python manage.py migrate`.
- **DEBUG=False**: PostgreSQL. Requires `.env` with `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`.
- Run `python manage.py migrate` before first use — the SQLite file may be empty.
- All models use **UUID primary keys** (`uuid.uuid4`). Do not use integer IDs.
- Custom user model: `AUTH_USER_MODEL = 'users_auth.User'` — always use `get_user_model()` or `'users_auth.User'` in relationships.

## Architecture

8 Django apps, each with models/views/serializers/urls:

| App | Purpose |
|---|---|
| `users_auth` | Custom User, Department, Role, Permission models |
| `patients` | Patient registration, allergies, alerts, documents |
| `clinical` | Visits, triage, encounters, orders, admissions, diagnostics |
| `pharmacy` | Medications, prescriptions, dispensing |
| `billing` | Price lists, invoices, payments, cashier shifts |
| `inventory` | Categories, items, stores, stock movements |
| `audit` | AuditLog model for change tracking |
| `reports` | HMIS/DHIS2 report generation with CSV/XLSX export |
| `exports` | Universal data export: CSV, Excel, PDF, Word, Image for all 21 data types |

API routes: `/api/auth/`, `/api/patients/`, `/api/clinical/`, `/api/pharmacy/`, `/api/billing/`, `/api/inventory/`, `/api/reports/`, `/api/export/<data_type>/?format=csv|xlsx|pdf|docx|png`

Template views are in `jfd_hms/views.py` and serve pages at root paths (e.g., `/opd/`, `/cashier/`, `/pharmacy/dispensing/`).

## Key patterns

- **Billing immutability**: `billing/signals.py` blocks deletion of `InvoiceLineItem` and `Payment` records. Financial records are append-only.
- **Invoice number format**: `JFD-INV-{YYYYMMDD}-{seq:05d}` (generated by `billing.services.generate_invoice_number()`).
- **MRN format**: `JFD-{year}-{sequence:05d}` (configured in settings as `HMS_MRN_FORMAT`).
- **Service price lookup**: `billing.services.lookup_service_price()` checks payer-specific prices first, then defaults. Always pass `payer_category` for correct pricing.
- **Order-to-invoice posting**: `billing.services.post_order_to_invoice()` auto-creates invoice line items from clinical orders.
- **Dispensing gate**: Pharmacy dispensing validates stock, checks expiry, deducts inventory, and posts to billing.
- **Triage routing**: Keyword-based department routing (ER for chest pain/trauma, OBGYN for pregnancy, OPD default).

## Testing

- Tests live in `tests/` directory (not per-app `tests.py` files, which are empty stubs).
- `tests/base.py` defines `BaseTestCase` with `create_all_tables()` / `drop_all_tables()` — it manually creates tables via Django's schema editor for each test run.
- Extends `django.test.TestCase` and DRF's `APIClient`.
- Seed data is auto-created in `BaseTestCase.setUp()` — no external DB setup needed.
- To run a single test class: `python manage.py test tests.test_patient_api.PatientAPITest`

## Environment

- `.env.example` documents all config vars. Copy to `.env` and fill in values.
- `SECRET_KEY` has a default insecure value — set a real one for anything beyond local dev.
- CORS is configured for `localhost:3000` by default (frontend dev server).
- Session timeout: 15 minutes. Session cookie is secure in production.
- Timezone: `Africa/Monrovia`.
- Email backend defaults to console (prints to stdout).

## Gotchas

- **No CI/CD or deployment config exists.** No Dockerfile, docker-compose, Procfile, or GitHub Actions.
- **No linting/typecheck tools configured.** No flake8, ruff, mypy, pylint, or pre-commit hooks.
- **CRITICAL: Django template tags inside HTML comments cause errors.** `<!-- {% include "foo" %} -->` is NOT a comment to Django — it's processed as an `{% include %}` tag. Use `{# #}` Django template comments instead. This caused a RecursionError crash on production for `/patients/register/` and `/clinical/triage/` because `webcam_upload.html` had `{% include %}` inside `<!-- -->`.
- Templates at `templates/pharmacy/dispensing.html`, `templates/billing/cashier.html`, and `templates/clinical/opd_consultation.html` reference `{% static %}` without `{% load static %}` — will crash if served via Django templates.
- `billing/signals.py` hardcodes `user_id=None` and `user_ip='127.0.0.1'` in audit logs — does not capture the actual request user.
- Seed data script (`seed_data.py`) imports models directly and expects `django.setup()` to have run.
- **CSRF:** `CsrfViewMiddleware` is in MIDDLEWARE. `CSRF_COOKIE_HTTPONLY = False` so frontend JS can read the cookie. Login view calls `get_token(request)` to ensure CSRF cookie is set for API calls.
- **Patient POST uses `PatientCreateSerializer`** which omits `id`/`mrn` from response — query back via GET to get full data.
- **Visit types are lowercase:** `opd`, `ipd`, `er`, `obgyn`, `surgery`, `pediatric` (not `OPD`).
- **Triage submit** requires visit status `checked_in` or `in_triage`. Use PATCH `/api/clinical/visits/<id>/status/` first.
- **Triage field is `heart_rate`** not `pulse_rate`.
- **Prescription requires** `patient` + `prescribed_by` fields (user UUID).
- **Prescription items** use `quantity_prescribed` + `duration` (not `quantity`/`dispense_quantity`/`duration_days`).
- **Diagnosis** `encounters/<id>/diagnoses/` needs `encounter` + `patient` + `visit` in POST body.
- **`place-order`** expects `order_type` + `items` array (not `order_description`).
- **Pilot reset:** `python manage.py pilot_reset` clears non-user tables, re-seeds everything, creates test users.
- **Registration visit types:** Form offers 5 options: OPD, Emergency, Pediatric, OBGYN, Surgery. All create a Visit with `status='checked_in'`.
- **Ward bed occupancy:** Surgery dashboard shows Surgical Ward 1 beds (`ward_type=surgical`). OBGYN dashboard shows Maternity Ward beds (`ward_type=maternity`). Filter via `GET /api/clinical/beds/?ward_type=surgical`.
- **SurgicalCase/AntenatalVisit admission FK:** Both models have nullable `admission` FK. When a bed is selected in the case/ANC form, an Admission is auto-created in the appropriate ward.
- **UserListView permission:** Changed from `USER_MANAGE` to `ENCOUNTER_VIEW` — doctors/nurses can now list users for surgeon selection dropdowns.
- **AntenatalVisit required fields:** `lmp_date` (DateField, NOT NULL), `edd_date` (DateField, NOT NULL), `ga_weeks` (IntegerField, NOT NULL). EDD auto-calculated from LMP (+280 days).
- **Export system:** `/api/export/<data_type>/?format=csv|xlsx|pdf|docx|png` — 21 data types: patients, visits, triage, opd, emergency, ipd, appointments, surgery, obgyn, labor, delivery, births, postnatal, prescriptions, dispensing, invoices, payments, stock, inventory, audit, users. Template tag: `{% load export_tags %}{% export_buttons "patients" %}`.
- **Registration fee:** `HospitalSetting.registration_fee` (DecimalField, default=$5.00) — charged automatically via `post_registration_fee_to_invoice()` on every registration (template, API, and clinical-first flows).
- **Patient photo:** `Patient.photo` is an `ImageField(upload_to='patients/photos/')`. Registration form uses `enctype="multipart/form-data"` and `capture="user"` for front camera.
- **Triage-First workflow:** `/clinical/triage-pending/` shows patients with `status='pending_registration'`. Clicking "Complete Registration" opens the registration form with `?visit_id=<uuid>` — the view links the new patient to the existing visit instead of creating a new one.
- **Follow-Up Queue:** `/clinical/follow-up-queue/` queries `Visit` objects where `is_follow_up=True` and `follow_up_date` is within configurable window (`HospitalSetting.followup_window_days`, default=30).
- **Discharge with Follow-Up:** Nurse Notes page has "Discharge Patient" button that opens a modal with follow-up date picker. On save: `API.updateVisitStatus(visitId, 'completed')` + creates follow-up `Appointment`.
- **HospitalSetting singleton:** `HospitalSetting.get_settings()` returns the single row (auto-creates if none exists). New fields: `registration_fee`, `followup_window_days`.
- **Sidebar is role-based:** Each sidebar link checks both permission AND role. A triage nurse only sees Triage + Triage Queue. A pharmacist only sees Pharmacy. See `templates/base.html` for the full role-to-link mapping.
- **Webcam + Document Upload:** Reusable partial at `templates/partials/webcam_upload.html`. Uses `navigator.mediaDevices.getUserMedia()` for webcam. Files saved via `default_storage.save()` to cloud/local storage. PatientDocument uses `file_url` CharField (stores URL string, not FileField).
- **TriageRecord.photo:** `ImageField(upload_to='triage/photos/')` — added in migration `0013_triagerecord_photo`. Triage form passes `files` to `process()` method.
- **Patient Profile:** `/patients/<uuid>/profile/` — view at `jfd_hms/views.py:patient_profile`. Shows demographics, documents, visits, triage history, invoices.
- **Document storage:** `PatientDocument.file_url` stores the URL returned by `default_storage.url(path)`. In production (Cloudinary), this is a CDN URL. In local dev, it's `/media/...`.
- **Sidebar SOP order:** Triage → Triage Queue → Register Patient → Search → OPD → Nurse Notes → IPD → ER → Pediatric → OBGYN → Surgery → Diagnostics → Pharmacy → Billing → Inventory → Reports → Appointments → Follow-Up → Admin.
